# 方向二与主项目融合说明

## 一、放在流程的哪个位置

主项目现有的链路是：疾病表型 → 异质图传播 → 基因排序 → 模块发现。方向二插在最后一段，不改变前面的排序，只在排序结果上做模块选择与可靠性评价。

输入：一份分数矩阵（疾病 × 基因），或一份候选模块清单。
输出：每个疾病一个（或一组）模块，附带可靠性分数与 A/B/C 等级。

不改变的东西：传播分数、图结构、折划分、候选基因集合。

## 二、模块表字段

一行是一个疾病—模块。字段如下。

| 字段 | 类型 | 说明 |
|---|---|---|
| module_id | string | 形如 `MONDO:xxx:selected` |
| disease_id | string | MONDO ID |
| gene_id | string | Entrez ID，一模块多行或逗号分隔 |
| size | int | 模块基因数（本方向统一 25） |
| z_spec | float | 疾病特异性，背景为 20 个表型相似但不同家族的疾病 |
| p_spec | float | 随机表型零模型下的 p，100 次抽样，地板 0.0099 |
| q_spec | float | 折内 BH 校正后的 q |
| core_jaccard | float | 核心成员 Jaccard（τ=0.8，两半扰动互比） |
| replication | float | 独立扰动中的复现率（覆盖 ≥60%） |
| density | float | 模块内边数 / 完全图边数 |
| hub | float | 最大加权度 / 模块加权度之和 |
| go_fdr | float | 最佳 GO 条目的 BH FDR |
| tier | string | T1/T2/T3，按已知基因数分层 |
| grade | string | A/B/C |

A 级判据：p_spec ≤ 0.01、replication ≥ 0.7、hub ≤ 0.5、go_fdr ≤ 0.05。

## 三、三个接口

**单模块打分**

输入：疾病 ID、基因列表、可选的分数矩阵版本。
输出：上表除 module_id、grade 外的全部字段。
用途：主项目给出一个候选模块，判断它是否可靠。

**批量分级**

输入：模块清单（疾病 + 基因列表）。
输出：同一张表加 grade。
用途：给一批已有模块打等级，不需要重跑发现流程。

**重跑流程**

输入：新的分数矩阵或新的折划分。
输出：完整的模块表与分级结果。
用途：换数据后重现方向二的结果。

三个接口都依赖同一份数据链（10 张表）与同一个候选基因全集，缺失时直接报错，不做静默降级。

## 四、三条边界

**第一，分数只对进入候选集的基因有效。** 已知心血管基因的传播分位中位数是 0.94，也就是排在前 6%，而模块只取前 1.2%，所以只有约三成能进候选。可靠性分数回答的是“这个模块作为模块是否可靠”，不回答“这个基因是不是致病基因”。拿它做疾病基因优先化会失望。

**第二，GWAS 类证据要在度数匹配口径下解释。** 用“同大小随机基因集”做对照时，基线模块因为 hub 密集会天然占优；换成同度数分位的替代基因后，两者无显著差异。若主项目沿用旧口径，会得出“方向二的模块更差”的错误结论。

**第三，跨网络比较只能做社区富集。** 两个网络切出的模块成员几乎不重叠，按“60% 成员重合”去比，两边都接近零；改成“模块基因在目标网络社区里是否超几何富集”才可比。

## 五、接入后的验收

用现有的 452 个疾病跑一遍，应当复现下列数字，误差在抽样波动内：

A 级 50.9%（基线 22.6%），样本外 z 0.858（基线 0.722），core Jaccard 0.9125（基线 0.8466），复现率 0.853（基线 0.730），密度 0.360（基线 0.253），hub 0.156（基线 0.182）。

任何一项偏差超过 0.01，说明数据链或折划分被改动过，需要先对齐再接入。

## 六、维护

模块表、接口与本文档随递交包版本走。当前版本 v2.6，对应 Release 与仓库提交见包内 README。

主项目若要改候选集大小（默认 200）或模块规模（默认 25），需要重跑精修与分级；这两项参数与敏感性结果已在五折总结里，K=500 的对照表明放宽候选集会显著降低特异性，不建议改。
