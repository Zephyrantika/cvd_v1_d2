# 评测口径对齐（R7）

对照 DREAM 模块识别挑战（Choobdar et al., Nature Methods 2019）与 PhEval（BMC Bioinformatics 2025），检查我们的评价体系缺什么、哪些指标可以映射过去。

## 一、DREAM 的评测清单与我们的对应

DREAM 挑战评比 75 种模块识别方法，核心是「模块是否与外部性状信号吻合」。它的几项要求与我们现有的对照关系：

| DREAM 要求 | 我们的对应 | 状态 |
|---|---|---|
| 从同一网络、同一候选集出发 | 统一 top-200 → STRING 700 → Leiden | 满足 |
| 模块与 GWAS 信号的富集 | 模块的 `gwas_z`（相对同大小随机基因集） | 已有，未进主表 |
| 不同规模下的稳定性 | 规模扫描 15/20/25/30/40 | 已有 |
| 跨网络/跨数据集复现 | STRING 700 与 HumanBase 心脏网络 | 部分（HumanBase 只做了 z，未做全指标） |
| 显著性校正 | 折内 BH、100 次零模型 | 满足 |
| 分层报告 | T1/T2/T3 分层 | 满足 |

缺的两项：GWAS 富集没有作为主指标报告；跨数据集复现只做了 z 一项，没有复现率与结构指标。

## 二、PhEval 的口径与我们的对应

PhEval 是表型驱动基因优先化的评测框架，强调三件事：按疾病分层、用同一套指标横向比较多个工具、报告运行配置。

| PhEval 要求 | 我们的对应 | 状态 |
|---|---|---|
| 按疾病分层报告 | T1（≥5 基因）/T2（3–4）/T3（1–2） | 满足 |
| 多工具统一输入输出 | 九种方法对照，同候选集同规模 | 满足 |
| 报告运行时与配置 | 各脚本 qc JSON + `docs/VERSIONING.md` | 基本满足 |
| 无标签泄漏的评测 | 交叉拟合 z（半表型建模块、半表型评价） | 满足 |
| 指标含义明确 | z_spec / 复现率 / A·B·C 分级 | 需补文档 |

需要补的：A/B/C 阈值没有给出外部依据，目前是自定的；应写成「对齐 PhEval 的分层思想，阈值按本项目数据分布确定，并在文中给出敏感性」。

## 三、指标映射表

| 我们的指标 | 最接近的外部口径 | 差异 |
|---|---|---|
| z_spec | DREAM 的「trait association」 | 我们用表型传播分位，DREAM 用 GWAS 富集 |
| 独立扰动复现率 | DREAM 的「stability across perturbations」 | 我们做了 20 次独立扰动，DREAM 用多方法集成 |
| A/B/C 分级 | PhEval 的分层报告 | 我们是阈值制，PhEval 是排序制 |
| 交叉拟合 z | PhEval 的 held-out 评测 | 我们用表型分半，PhEval 用基因留出 |

## 四、不建议混用的地方

DREAM 的 GWAS 富集口径与我们现有的 `gwas_z` 不同：前者按模块内 GWAS 命中基因的比例做超几何检验，后者是相对同大小随机集的标准化差值。两者结论方向可能一致但数值不可互换，文中若同时出现必须写清各自定义。

## 五、建议补充的三项

1. 把 `gwas_z` 提到主表，与 z_spec、复现率并列，回应 DREAM 的性状关联要求。
2. 跨网络复现补齐：在 HumanBase 心脏网络上算复现率与结构指标，而不只算 z。
3. A/B/C 阈值写一段敏感性分析（阈值上下浮动 0.05，看 A 级比例变化），回应 PhEval 对阈值任意性的质疑。

## 六、结论

口径上我们没有硬伤：分层、零模型、多重检验、跨方法比较都齐。缺的是「外部性状关联」作为主指标，以及跨数据集复现的完整性。这两项补上，评测部分就能按 DREAM/PhEval 的语言写。
